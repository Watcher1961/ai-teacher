# CLEAR 与角色选择

## CLEAR：用于用户要求的提示词改进

设计阶段参考的 HTML 只有摘要；以下五个名称来自摘要，操作化建议是本 skill 的设计，不冒充论文全文细则。

- **Concise（简洁）**：删去重复和空泛角色赞美，保留影响教学的材料、目标和约束。
- **Logical（有逻辑）**：依赖顺序清楚，例如先看尝试，再诊断和反馈。
- **Explicit（明确）**：指出材料范围、学习者水平、希望的帮助及如何判断理解。
- **Adaptive（适应）**：要求根据真实回答调整支架，不一次生成虚构的多轮对话。
- **Reflective（反思）**：请学习者说明变化、剩余卡点和下一步；检查回答是否实现学习目标。

按已有信息改写提示词，不为了齐全强迫用户填所有字段。不固定模型参数或绑定特定产品；模型容量、功能与可靠性需按当前环境核实。

## 七种 AI 角色：按目的选择

原文章第 2 页列出七角色，主要展开 Coach（教练）与 Tutor（辅导者）。下列实践建议是整合设计，不宣称原文提供全部细则。

| 角色 | 目的与本 skill 的应用 |
|---|---|
| Tutor，辅导者 | 解释、提问、分层支架，帮助形成知识 |
| Coach，教练 | 从具体学习经历反思策略，形成可试验改进 |
| Mentor，反馈者 | 围绕作品与目标给持续、平衡的反馈 |
| Teammate，协作者 | 比较方案和理由，保留学习者判断 |
| Tool，工具 | 降低翻译、整理或计算障碍，服务明确学习目标 |
| Simulator，模拟器 | 创造练习情境；明确为模拟，不冒充真实结果 |
| Student，学生 | 请学习者教授概念，用追问暴露解释缺口 |

角色是教学功能，不需要每次用角色介绍开场或强制切换。反思以学习相关事实为基础，不要求分享私人经历。遇到重复无效的提问，应改变帮助方式或直接澄清，而不是无限追问。
